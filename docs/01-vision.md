# 01. 비전

## 한 문장

컴퓨터 앞에서 일하고 공부하는 사람이 **몰두한 시간을 기록하고 되돌아보게** 하며, 그 시간이 자기 마을로 쌓여 가는 것을 보며 뿌듯함을 느끼게 하는 서비스.

## 목적 (우선순위 순)

1. **몰두**: 시작 버튼 하나로 몰두에 들어가고, 방해 없이 유지하고, 끝나면 되돌아본다.
2. **회고**: 몰두가 끝날 때마다 한 번의 탭으로 "어땠는지"를 남긴다. 이 기록이 사용자에게는 자기 이해가 되고, 서비스에는 가장 가치 있는 데이터가 된다.
3. **뿌듯함**: 몰두로 얻은 코인으로 마을을 꾸민다. 마을은 하찮으면 안 된다. 시간을 들인 만큼 보기 좋아야 한다.

## 비목적

- 감시 도구가 아니다. 켜두고 자리를 비우는 사용자를 잡아내려고 애쓰지 않는다. 회고 시점에 스스로 알아차리면 충분하다.
- 소셜 네트워크가 아니다. 이웃·길드는 나중이며, 있어도 몰두를 방해하지 않는 선에서만 존재한다.
- 게임이 아니다. 마을은 보상이지 경쟁이 아니다. 랭킹은 만들지 않는다.

## 설계 원칙

- **집중 모드와 마을 모드는 분리한다.** 첫 화면은 타이머다. 마을은 몰두가 끝난 뒤 가는 곳이다.
- **마찰 최소.** 세션 시작에 필수 입력은 없다. 회고 필수 항목은 탭 두 번(기분, 의도 일치)으로 끝난다.
- **서버가 진실이다.** 시간 집계, 보상 계산, 상태 전이는 모두 서버에서 일어난다.
- **모든 행동은 이벤트로 남는다.** 데이터 엔지니어링 프로젝트로도 성립해야 한다.
- **비용 0원.** 수익화 전까지 유료 서비스를 쓰지 않는다.
- **디자인은 로직 다음.** 서비스 로직이 전부 동작한 뒤 디자인 패스를 따로 한다. 그때까지 UI는 기능만 드러내는 최소 형태를 유지한다.

## 대상 사용자

컴퓨터 앞에서 작업·공부·업무를 하는 사람. 데스크톱 브라우저가 1순위, 모바일 브라우저(PWA)가 2순위. 네이티브 앱 설치는 강제하지 않는다.

## 단계

| 단계 | 범위 |
|---|---|
| M0 | 문서 + 스캐폴드 |
| M1 | 집중 코어: 인증, 세션 상태 머신, heartbeat, 회고, 보상 원장 |
| M2 | 마을: 카탈로그, 구매, 격자 배치, 레벨 |
| M3 | 알림: Web Push, 크론 디스패치, 주간 이메일 |
| M4 | 데이터 파이프라인: 이벤트 → Parquet → dbt-duckdb → 대시보드 |
| M5 | 길드 마을, 이웃 방문, 디자인 패스 |
