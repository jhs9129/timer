# ADR 0002. 몰두 시간은 서버가 heartbeat로 계산한다

상태: accepted (2026-09-17)

## 맥락

몰두 시간은 보상의 근거이자 서비스의 핵심 데이터다. 클라이언트가 "N분 집중했다"고 보내는 값은 조작 가능하고, 탭이 닫히거나 기기가 잠들면 정확하지 않다. 그러나 서비스는 감시 도구가 아니므로 완벽한 검증을 목표로 하지는 않는다.

## 결정

- 클라이언트는 `running` 동안 30초마다 heartbeat만 보낸다. 경과 시간을 보내지 않는다.
- 서버는 세션당 세그먼트(`started_at`, `last_seen_at`, `ended_at`)를 관리한다. heartbeat가 90초 이상 끊기면 세그먼트를 `last_seen_at`에 닫고 세션을 `paused(timeout)`으로 전환한다.
- `focused_seconds`는 닫힌 세그먼트 길이의 합이다.
- 클라이언트 표시 타이머는 서버가 준 `focused_seconds`와 `running_since`로 로컬에서 그린다.

## 대안

- 클라이언트 보고 신뢰: 구현이 가장 쉽지만 데이터 품질을 보장할 수 없다. 이 데이터를 파이프라인 프로젝트에 쓸 계획이므로 기각.
- 요청마다 서버 시각 기록 없이 start/stop만 기록: 탭이 닫힌 채 방치된 시간이 전부 집계된다. "켜두고 나감"을 막지는 않지만 탭이 닫힌 시간까지 세는 건 사용자 정책과도 어긋난다.

## 결과

- 세션 관련 요청 하나가 늘고(heartbeat), DB 쓰기가 30초마다 발생한다. 세그먼트 한 행 갱신이라 부담은 작다.
- 오프라인 상태에서의 몰두는 집계되지 않는다. 의도된 제약이다.
- 유휴 감지(클라이언트)와 timeout(서버)이 이중으로 동작한다. 둘 다 `paused`로 수렴하므로 충돌하지 않는다.
